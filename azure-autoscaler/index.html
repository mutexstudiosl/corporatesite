The Problem

Azure scales some things.
Not all things.

Critical PaaS resources on Azure are flexible but don't autoscale. You end up continuously monitoring and scaling manually — a time-consuming task that leads to overprovisioning and unnecessary cost. Or worse, the autoscaling features that do exist simply fail in edge cases.

Azure Autoscaler closes that gap with a self-hosted, containerized solution that monitors your resources and scales them intelligently — based on real-time metrics, forecasting, or defined schedules.

Custom metrics

Publish the series Azure does not have.

A custom metric is written into Azure Monitor and charted next to the platform metrics. Node pool node count. On Azure SQL, replica DTU, memory, and replica latency. The rule then reads those series the same way it reads dtu_used.

replica_dtu_used and dtu_used

replica_dtu_used dtu_used Example. The replica series is custom. dtu_used is the platform metric.

Lambdas in the rule

Transform and ScaleTarget are C# lambdas. This one reads FileCapacity, converts the average to GB, and sets provisioned storage to that plus 50 GB.

ScalingConfigurations:
  Baseline:
    Metrics:
      FileCapacity:
        Name: FileCapacity
        ResourceId: "/subscriptions/${subscriptionId}/resourceGroups/${resourceGroupName}/providers/Microsoft.Storage/storageAccounts/${storageAccountName}/fileServices/default"
        Window: 02:00:00
        TimeGrain: 01:00:00
        SplitName: "FileShare"
        SplitValue: "${fileShareName}"
        Aggregations: ["Average"]
        Transform: "(value) => value.SetAverage(value.Average / (1000 * 1000 * 1000))" # Convert to Gb
    TimeWindow:
      Days: All
      Months: All
      StartTime: "00:00"
      EndTime: "23:59"
      TimeZone: UTC
    ScalingRules:
      fixed:
        ScalingStrategy: Fixed
        Dimension: ProvisionedStorage
        # Fixed +50 GB above whatever is being used
        ScaleTarget: "(data) => (data.Metrics[\"FileCapacity\"].Values.First().Average + 50).ToString()"
        DimensionValueCeilingStep: "1"  # Round up to nearest GB
        DimensionValueMin: "100"  # Minimum 100 GB for Azure Files

Features

Smart scaling, zero babysitting

Self-Hosted

Runs as a containerized application in your AKS cluster or Azure Container Services. Your data never leaves your environment.

Schedule-Based Scaling

Scale up before business hours, scale down overnight. Define schedules that match your real traffic patterns and save money when resources are idle.

Flexible Metric Analysis

Write custom scaling rules using Lambda expressions evaluated against real-time Azure Monitor metrics. Total control without code changes.

Usage Forecasting

Custom forecasting algorithms predict future demand and scale proactively — before load spikes cause degraded performance.

Multidimensional Scaling

Target multiple dimensions for the same resource — CPU, memory, IOPS, available storage. The system automatically picks the best available SKU or scales each dimension independently when the resource supports it.
